# 改善ループ記録(2 周)

このセットは「v1 ドラフト → 批評 → 改訂(ループ 1)→ 再批評 → 改訂(ループ 2)」の手順で作成しました。何をなぜ変えたかの記録です。講座を実施したら、このファイルに「ループ 3(実施後の振り返り)」を追記していくことを推奨します。

## ループ 1: 「本当にその時間で回るか・本当に持ち帰れるか」

v1 に対する批評レンズ: 時間配分の現実性/初心者のつまずき先回り/「明日使える」への直結度/機能理解の正確さ/講師も初心者という前提。

| # | 指摘 | 対応 |
|---|---|---|
| 1 | 60 分版でセットアップ 5 分+選択制ハンズオン 10 分は初心者集団では破綻する(3 メニュー説明だけで数分溶ける) | 60 分版は「1 サイクル(生成→検証→改善→保存)を 1 本だけ」に全振り。選択制は「早く終わった人の第 2 メニュー」に格下げ。セットアップは受付時に前倒しし「開始前に環境が揃っている」を成立条件として明記 |
| 2 | 「AI 提案フィードバックを体験」と書いたが、提供状況・管理者設定に依存し受講者環境で使えない可能性が高い | 全版で「講師デモのみ。皆さんの環境で使えるかは管理者設定次第、と正直に言う」に修正 |
| 3 | 生成して満足して終わり、保存方法が講座に入っていない → 持ち帰れない | ハンズオン手順の最終ステップに「Docs へ書き出して保存」を組み込み。講師チェックリストにも保存方法の事前確認を追加(「受講者が一人で最初に詰まるのはここ」) |
| 4 | 講師 1 人で何人まで見られるかが未定義 | 推奨定員(対面 12〜16 人、オンライン補助ありで 20 人)と、超過時のサポーター任命ルールを明記 |
| 5 | 講座後、職員室で一人になった瞬間に手が止まる問題への手当てがない | プロンプト集末尾に「今夜やること 3 ステップ(15 分)」を追加。1 週間後フォローフォーム+質問受付を全版共通設計に |
| 6 | 「Gemini タブが出ない」受講者への出口が「後日問い合わせて」で終わっていた | そのまま送れる「管理者への依頼文面」をプロンプト集に同梱。オンライン版は事前チェックフォームで前日までに検出して文面を先送り |
| 7 | 複式学級・少人数校の文脈がプロンプト集にしかなく、講座本体に出てこない | 90/120 分版の選択制に「D: 難易度別・複式学級の間接指導課題」を追加 |
| 8 | 冬のオホーツクで対面講座が飛ぶリスクに触れていない | 対面版に「前日 15 時判断でオンライン 60 分版に切替」の荒天対応を追加 |
| 9 | 実技系教科(体育・音楽・美術)の受講者にテスト生成は刺さらない | 「ワークシートか導入ネタでも可」を全ハンズオンに明記 |
| 10 | デモ中に都合よく AI が間違えなかったら「検証が必要」の実演ができない | 講師チェックリスト Phase 2 で「間違い生成例のスクショを事前に確保」→ デモ台本に「出なければスクショで同じ話をする」を明記 |
| 11 | 講師の練習時間見積もり(Phase 1: 2〜3 時間)が楽観的 | 4〜5 時間に修正し「1 日 1 時間×1 週間」のペース提案を追加。デモ用サンプル課題ファイルの準備、失敗談の用意も追加 |
| 12 | 録画配布(オンライン)の肖像・発言の扱いが未整理 | 冒頭での録画告知・配布範囲の同意・顔出しなし参加 OK を明記 |
| 13 | 翻訳機能を保護者文書にそのまま使うと誤訳リスク | プロンプト集と 120 分版に「重要文書は必ず確認者を通す」を追加 |

## ループ 2: 「ファイル間の整合・受講者体験の通し・選び方」

改訂版に対する批評レンズ: ファイル間の不整合/講座前後の体験の切れ目/主催者目線(どの枠を選ぶか)。

| # | 指摘 | 対応 |
|---|---|---|
| 1 | 講師チェックリスト Phase 3 のデモ台本(テスト→ルーブリック→誤解対応)が、改訂後のデモ(テスト→条件追加→保存)と食い違っていた | チェックリスト側を修正して一致させた |
| 2 | 対面版の事前・事後アンケートの回収方法が未指定(初任者は「アンケートやります」だけでは動けない) | 「紙または QR フォーム、受付机に両方」を明記 |
| 3 | README に「60/90/120・対面/オンラインをどう選ぶか」の指針がなく、主催者(教頭・研修担当)が使いにくい | README に「講座の選び方」表を追加 |
| 4 | 効果測定(同じ 3 問の事前事後比較)と事後フォローが講座ファイルにしかなく、セット全体の設計として見えない | README の選び方セクションに共通設計として明記 |

## ループ 3: 初任段階特化 — 「時間×質」の 2 軸で磨く(2026-08 実施)

依頼: 効率(時間と質の二軸)の観点で、①よい授業をつくる ②学級経営の手立て に刺さるセットへ。それ以外の良い使い方も初任の想定にかけて磨く。

| # | 判断 | 対応 |
|---|---|---|
| 1 | 旧版は「時短」に寄っていて、使うほど腕が上がる設計になっていなかった | 「時間の軸(下書きを任せる)×質の軸(壁打ちで引き出しを増やす)」のフレームを README・両講座の冒頭 1 分・プロンプト集の背骨に据えた |
| 2 | 授業づくりの「質」に効く道具が誤解対応くらいしかなかった | **発問の壁打ち・子ども役シミュレーション・授業の振り返り壁打ち**をプロンプト集に追加し、90/120 分版のハンズオン③を「質の壁打ち」に改称・組み替え |
| 3 | 学級経営がほぼ空白だった(初任の困り感の半分はここ) | 第 2 部「学級経営の手立て」を新設: 学級通信・朝の会ネタ・吹雪の日の室内レク・声かけの引き出し・トラブル対応の前整理・係活動・席替え・保護者電話の前整理・懇談想定問答・学級目標。60 分版のハンズオンを「授業コース/学級経営コース」の 2 コース制に(初任には締切の近い学級通信が刺さる) |
| 4 | 初任ならではの場面が未カバー | 第 3 部を新設: 研究授業の指導案ブラッシュアップ、初任研レポートの構成、未経験部活の練習メニュー、週の段取り相談。120 分版ハンズオン④を「校務への応用」から「学級経営・初任の一年」に差し替え |
| 5 | 保護者対応は初任が一番事故りやすい | 鉄則「AI 下書き → 自分で直す → 指導教員・管理職のチェック」を約束事に昇格し、Q&A 台本にも「保護者向け文書も AI でいい?」を追加。電話プロンプトに「かける前に主任・管理職へ一報」を明記 |
| 6 | トラブル相談系は個人情報リスクと隣り合わせ | 「状況は具体的に、個人は抽象的に(誰がではなく、どんな状況が)」の抽象化ルールをプロンプト集・Q&A・講師練習(Phase 1)の三箇所に配置。AI は同僚・管理職への相談の**代わりではなく前整理**という位置づけを明文化 |
| 7 | 講師の事前練習が授業系機能に偏っていた | Phase 1 に学級経営・壁打ち系の練習(通信の所要時間計測、発問壁打ち、子ども役、抽象化の練習)を追加 |
| 8 | プロンプト集が機能別で、初任の頭の中(困り事別)と合っていなかった | 20 本 → 30 本に拡充し、「第 1 部 よい授業/第 2 部 学級経営/第 3 部 初任ならでは+校務」の 3 部構成に再編。時短系と質系をラベルで区別 |

## ループ 4: 研究知見への接地と「初任段階レンズ」の新設(2026-08 実施)

契機: 真田・蘭(2024)北海道教育大学紀要 74(2) の提供を受け、講座の前提を実証データと照合。あわせて「初任段階の視点を静的にせず、データで更新し続ける」仕組みの要望に対応。

| # | 判断 | 対応 |
|---|---|---|
| 1 | 初任者困難の研究的裏づけが資料に皆無だった | 論文を README・註・Notebook ソース集に追加 |
| 2 | 「初任の困り感の半分は学級経営」というループ 3 の想定は、データでは不正確(学級経営の困難度は相対的に低く、最大は授業×多忙) | 2 大「困り感」→ 2 大「テーマ」に言い換え、困難構造の説明をデータに合わせて修正。2 軸(時短→教材研究の時間を取り戻す)の語りに実証根拠がついた |
| 3 | 「叱れない・けじめをつけられない」は 1 年目の終わりまで残る困難だが、声かけプロンプトは「叱らない」方向のみだった | プロンプト 20b「毅然と伝える練習」を追加し、両輪に |
| 4 | 困難を下げる最大の要因は「相談しやすい環境」「被援助志向性」— AI 活用が一人で抱え込む方向に働くリスクがあった | キーメッセージ「AI は相談の代わりではなく、相談への一歩目」をクロージング台本・Q&A に明文化 |
| 5 | 初任視点が各ファイルに分散し、静的で、更新の仕組みがなかった | **[05_初任段階レンズ.md](05_初任段階レンズ.md) を新設**: 知見サマリー(出典・日付つき)、知見→反映対応表、観測データログ、更新プロトコル(研究検索・実施データ・Notebook 連携)を一元化。設計時に必ず通すフローを README に明記 |
| 6 | オホーツク特有の「相談相手が物理的に少ない」問題は研究の射程外 | レンズに検証仮説として登録し、事後アンケートへの項目追加(「校内に相談できる人がいるか」)を提案 |

## ループ 5: 高平ら(2014)の取り込み — レンズ更新フローの初稼働(2026-08 実施)

契機: 高平ら(2014)玉川大学紀要(真田・蘭 2024 の引用文献)の提供を受け、レンズの更新プロトコル(ソース追加 → 影響確認 → レンズ更新 → 講座反映)を初めて実運用。

| # | 判断 | 対応 |
|---|---|---|
| 1 | 「授業が最大の困難」が独立した 2 調査で一致。授業困難の内訳(時間確保・見通し・経験不足)も判明 | レンズ知見 1 を強化。内訳と講座要素(時短/指導案概要/子ども役)の対応を明記 |
| 2 | **新任時の困難第 2 位「発達障害が疑われる児童への対応」が講座セットの空白だった**(最大の原因は知識不足) | プロンプト 21b「気になる子への対応の引き出し」を新設(AI に診断させない・コーディネーター連携が本筋・相談の前整理という位置づけ)。選択制 D を「個に応じた支援」に拡張 |
| 3 | 初任者研修そのものが大きな負担(毎週の指導案・報告書・出張) | プロンプト 27・28 に実証的裏づけ。120 分版④で「初任研こそ AI 下書きが効く」と明示 |
| 4 | 校務分掌は 2 年目以降に困難トップ(唯一増える項目) | 2〜3 年目参加者への案内をレンズに登録 |
| 5 | 初任時に困難が高い教師は後年も高いまま(相関) | 初任段階を対象とする本講座の設計根拠として登録。相談ネットワークの意義を補強 |
