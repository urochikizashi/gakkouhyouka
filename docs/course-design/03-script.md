# 工程3: 台本・教材の量産

## 5ステップ・メソッド

台本をAIに「書かせる」のではない。AIに**質問させて、自分から引き出させる**。
出力の質を決めるのは、プロンプトの巧拙ではなく食わせたナレッジの量である。

```
① ナレッジを食わせる
      ↓
② ゴールシークプロンプトでAIに質問させる
      ↓
③ AIからの質問に箇条書きで回答する
      ↓
④ 出力を声に出して読み、違和感を修正する
      ↓
⑤ 3〜4割、自分の体験と哲学を反映させる
```

各ステップを飛ばしたときに何が起きるかを把握しておく。

| 飛ばすと | 起きること |
| --- | --- |
| ① | 一般論しか出ない。検索で読める内容になる |
| ② | 自分が説明を忘れている前提が埋まらない |
| ③ | AIが空白を推測で埋め、事実でない記述が混ざる |
| ④ | 読めるが**話せない**文章になる。動画で不自然になる |
| ⑤ | 誰が作っても同じ教材になる。選ばれる理由が消える |

## ① ナレッジを食わせる

投入するもの:

- 過去に自分が書いた台本・記事・スライド
- Q&Aログ（→ [inputs/qa-log.md](inputs/qa-log.md)）
- 工程1・2の成果物（コンセプトと学習マップ）

**自分の語彙・言い回し・比喩が入った文章**を優先する。
一般的な参考資料より、質の低い自分の過去原稿のほうが役に立つ。文体を学ばせるためである。

## ② ゴールシークプロンプト

AIに書かせる前に、**AIに質問させる**。そのままコピーして使う。

```
あなたはこれから、私の講座の第○章の台本を作成します。
ただし、いきなり書き始めないでください。

まず以下を読み込んでください。
- docs/course-design/01-concept.md（コンセプト）
- docs/course-design/02-curriculum.md（学習マップ）
- docs/course-design/inputs/qa-log.md（受講生の質問ログ）
- （過去の台本のパス）

読み込んだ上で、この章の台本を私の代わりに書くために
「あなたに足りていない情報」を質問の形で列挙してください。

条件:
- 質問は最大10個
- 重要な順に並べる
- 一般論で埋められる質問はしない。私にしか答えられないことだけ聞く
- 私の実体験・失敗談・判断基準を引き出す質問を優先する
- 質問だけを出力し、台本は書かない
```

出た質問が調べれば済む内容ばかりなら、①のナレッジが足りていない。戻る。

## ③ 箇条書きで回答する

**文章で答えない。箇条書きで答える。**

整った文章で答えようとすると、まとめる作業に時間がかかり、しかも構えた言葉になる。
断片で出したほうが、生々しい表現が残りやすい。

```
- 3年目のとき、集計を全部手作業でやって土日が消えた
- そのとき上司に言われた「で、これ誰が読むの?」が一番刺さった
- 結論: 集計より先に「誰が読むか」を決めないと全部無駄になる
```

回答したら、AIに台本を書かせる。

## ④ 声に出して読む

出力された台本を**必ず音読する**。黙読では引っかからない。

音読で見つかるもの:

- 一文が長すぎて息が続かない箇所 → 切る
- 自分が普段使わない語彙 → 自分の言葉に置換
- 論理は正しいが感情が動かない箇所 → 体験に差し替え
- 「〜であり、〜であるため」のような書き言葉 → 話し言葉に

この工程が講座教材と読み物を分ける。**書けるが話せない文章**をここで潰す。

## ⑤ 3〜4割を自分にする

AIの出力そのままでは、誰が作っても同じものになる。**3〜4割を自分の体験と哲学で置き換える。**

置き換える対象:

| AIが書いた形 | 置き換える形 |
| --- | --- |
| 一般的な成功例 | 自分の失敗談 |
| 教科書的な手順 | 自分が実際にやった順番と、詰まった箇所 |
| 「重要です」 | なぜ重要と考えるに至ったかの経緯 |
| 中立的な説明 | 自分の立場の表明（何をやらないと決めているか） |

4割を超えると、AIを使う速度の利点が消える。3割を下回ると、独自性が出ない。
