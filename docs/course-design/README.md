# 講座設計プロセス — ユーザファースト

講座を「作りたいもの」から作り始めない。**受講生がすでに口にしている言葉**から逆算して作る。
このディレクトリは、その手順を再現可能な形にしたものである。

## 貫かれている一つの原則

すべての工程で、判断基準を**作り手の都合から受講生の都合に置き換える**。

| 工程 | 作り手の都合（避ける） | 受講生の都合（採る） |
| --- | --- | --- |
| コンセプト | 自分が語れること | 顧客が悩みとして口にした言葉 |
| カリキュラム | 自分が教えたい順 | 受講生がつまずく順 |
| 台本 | 網羅的な正しさ | 声に出して違和感がないこと |
| 特典 | 数の多さ | メイン商品の弱点を埋めること |
| 仕上げ | AIの出力で完成 | 最後の5%に人間の体験を入れる |

この表に反する判断をしたときは、必ず理由を書き残す。

## 進め方

1. `inputs/` を埋める（人間の作業）
2. 工程1〜2をAIと対話しながら確定させる（`01-concept.md` / `02-curriculum.md` の各プロンプトを使う）
3. 工程3で台本を量産する
4. 工程4で特典を6基準で絞る
5. 工程5で最後の5%を人間が入れる
