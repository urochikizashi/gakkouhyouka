# 工程2: カリキュラム設計

## 考え方

**順序が9割。**

同じ内容でも、並べる順番だけで理解度と離脱率が変わる。
そして正しい順番は「自分が教えたい順」ではなく、**「受講生がつまずく順番」**である。

この2つは体系的に食い違う。

| 教えたい順（作り手の都合） | つまずく順（受講生の都合） |
| --- | --- |
| 前提知識 → 理論 → 実践 → 応用 | 最初の一歩が踏み出せない |
| 全体像から細部へ | 用語がわからず入口で止まる |
| 網羅的・体系的 | 途中で「自分の場合はどうなるのか」で詰まる |
| 例外・注意点を先に説明 | 例外を先に聞くと手が止まる |

作り手は自分がつまずいた記憶を失っている。だから記憶ではなく**ログ**に聞く。

## 手順

### 2-1. Q&Aログをつまずき順に整列させる

過去に受けた質問は「つまずきの実測データ」である。→ [inputs/qa-log.md](inputs/qa-log.md)

質問の**多さ**ではなく、質問が発生した**タイミングの早さ**で並べる。
早い段階で出る質問は、そこが離脱ポイントであることを意味する。

### 2-2. 学習マップを作る

受講生が自分の位置と残り時間を把握できる形にする。可視化する項目は2つ。

- **学習ゴール** — この節を終えたとき、何が「できるように」なっているか
- **所要時間** — 各節にどれだけかかるか

所要時間の明示は親切心ではなく設計上の必須要件である。
残り時間が見えない講座は、受講生が中断の判断すらできず、そのまま離脱する。

学習ゴールは動詞で書く。「〜を理解する」は測れないので使わない。
「〜を1枚作れる」「〜を判断できる」のように、達成が確認できる形にする。

## AIに渡すプロンプト

```
docs/course-design/inputs/qa-log.md と docs/course-design/01-concept.md を読み込んでください。

これは受講生から実際に出た質問のログです。以下を出力してください。

1. 質問を「受講生がつまずいた順番」に並べ替えてください。
   質問の件数の多さではなく、学習プロセスのどの段階で発生したかを基準にしてください。
2. つまずきが集中している箇所を特定し、そこを独立した章として切り出してください。
3. 各章について、学習ゴールを「〜できる」の形で1つ書いてください。
   「理解する」「把握する」は使わないでください。
4. 各章の所要時間を見積もってください。
5. 私が教えたくなりがちだが、受講生のつまずきログには現れていない内容を指摘してください。
   （それは後半に回すか、削る候補です）

ログにない箇所は「ログにない」と明示し、推測で補完しないでください。
```

最後の項目が重要である。ここで挙がる内容が、作り手の都合で前に来ていた部分にあたる。
