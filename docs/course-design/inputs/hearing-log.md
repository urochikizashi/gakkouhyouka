# 顧客ヒアリング記録

工程1（[コンセプト設計](../01-concept.md)）の入力。**10件を目標**に埋める。

## 書き方

**要約しないこと。話し言葉のまま貼ること。**

要約した瞬間に、翻訳すべき「生の言葉」が失われる。
講座名やキャッチコピーは、ここに書かれた言葉から直接取り出す。だから加工してはいけない。

| ✗ 書かないでほしい形 | ○ 書いてほしい形 |
| --- | --- |
| 業務効率化に課題を感じている | 「毎年これ、土日が丸ごと消えるんですよ」 |
| 分析手法に不安がある | 「集計はできるけど、で、これ何が言えるの?って言われると詰まる」 |
| 情報発信に苦手意識がある | 「保護者に配る一枚を作るのに、毎回3日悩んでます」 |

拾うべきもの:

- 口ぐせ、言い回しの癖、感情が出た言葉（「しんどい」「意味あるのかな」「怖い」）
- 諦めの言葉、愚痴、言いかけてやめたこと
- **困っている状態の描写**（本人が語る解決策より優先）

**新規に集める場合**: 「何に困っていますか」ではなく
「直近でいちばん時間を取られた作業は何でしたか」「そのとき何を思いましたか」と聞く。
前者は整った答えが返り、後者は生の言葉が返る。

## 学校現場での集め方

### すでに手元にあるもの（最優先）

新規にヒアリングを組む前に、過去に担当した講座から回収できる。こちらが速い。

1. **アンケートの自由記述** — 原文のまま転記する。要約された集計結果ではなく、生の記述
2. **終了後に来た質問** — その場で聞かれたこと。→ [qa-log.md](qa-log.md) にも入れる
3. **質問が来なかった回の記録** — 沈黙も情報である（工程0-7）

### 聞く質問（学校現場向け）

苦痛は「困っていること」と聞いても出てこない。**時間と場面**で聞く。

| ✗ 出てこない聞き方 | ○ 生の言葉が出る聞き方 |
| --- | --- |
| 業務で困っていることは? | 先週、いちばん時間を取られた作業は何でしたか |
| 生成AIに期待することは? | その作業をしているとき、何を考えていましたか |
| 研修で学びたいことは? | 何時に学校を出ましたか。持ち帰った仕事はありましたか |
| AI活用の課題は? | AIを使ってみようとして、やめたことはありますか。なぜやめましたか |

最後の質問が重要である。**「やめた理由」に現場の制約が入っている**（工程0-4）。
禁止されていると思った、個人情報が不安だった、端末で開けなかった、時間がなかった——
ここが競合の隙間を特定する材料になる。

### Well-being に接続する質問

HARM主軸（時間）から健康・人間関係へどう繋がるかを確認する。
ただし**「Well-beingについてどう思いますか」とは聞かない**。抽象的な答えしか返らない。

- その時間が空いたら、何に使いたいですか
- 最近、眠れていますか
- 家に帰ってから仕事のことを考えますか

### 注意

- 個人が特定される情報、児童生徒の情報は記録しない。苦痛の描写だけを残す
- 立場（担任／管理職／事務職員）は必ず記録する。苦痛が違い、ターゲット絞り込みの根拠になる
- 校種・学校規模も記録する（工程0の点検表「学校ごとの差」）
