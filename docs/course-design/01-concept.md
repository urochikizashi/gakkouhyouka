# 工程1: コンセプト設計

## 考え方

**商品は「作るもの」ではなく、「顧客の悩みという言葉を翻訳するもの」。**

自分の中から企画を絞り出す作業ではない。すでに顧客が発している言葉を、
商品名・キャッチコピー・カリキュラムという形に**翻訳する**作業である。

したがって、白紙から考え始めた時点で工程1は失敗している。材料は外にある。

## 手順

### 1-1. 生の声を10件集める

過去の顧客ヒアリング記録を10件ほど用意する。→ [inputs/hearing-log.md](inputs/hearing-log.md)

守るべき条件:

- **要約しない。** 「業務効率化に課題を感じている」ではなく「毎年アンケート集計に土日が丸ごと溶ける」と書く
- 言い回しの癖、口ぐせ、感情語をそのまま残す
- 解決策の提案ではなく、**困っている状態の描写**を拾う

生の言葉がそのまま商品名やコピーになる。だから加工してはいけない。

### 1-2. 3つの円が重なる点を特定する

```
        市場ニーズ
       （顧客が金を払う）
            ／＼
           ／  ＼
          ／ ★ ＼
         ／      ＼
   競合の隙間 ―― 自分の強み
（誰も埋めていない）（自分が語れる）
```

- **市場ニーズ**: 1-1の生の声に繰り返し現れる悩み
- **競合の隙間**: 既存の講座・書籍・研修が扱っていない領域
- **自分の強み**: 自分の実体験・失敗・独自の型

★ の重なりがコンセプトである。円が2つしか重なっていない企画は捨てる。

- 市場 × 競合の隙間のみ → 自分が語れず、内容が薄くなる
- 市場 × 自分の強み のみ → 既存商品に埋もれる
- 競合の隙間 × 自分の強み のみ → 誰も欲しがらない

### 1-3. HARMの4分類に当てはめる（必須）

人が金を払う悩みは4つに集約される。**どれに当てはまるか明示できないコンセプトは通さない。**

| 分類 | 領域 | 悩みの形 |
| --- | --- | --- |
| **H** — Health | 健康・美容・容姿 | 身体がつらい、見た目が気になる |
| **A** — Ambition | 野心・将来・キャリア | このままで終わりたくない、認められたい |
| **R** — Relation | 人間関係・恋愛・家族 | 人とうまくいかない、孤立している |
| **M** — Money | お金・収入・時間 | 足りない、損している、時間が奪われている |

複数にまたがってよいが、**主軸を1つに決める**。主軸が曖昧なコピーは刺さらない。

「便利になる」「効率化できる」はHARMではない。その先の「土日が家族に戻る（R/M）」
「評価が上がる（A）」まで翻訳して初めてHARMになる。

## AIに渡すプロンプト

`inputs/hearing-log.md` を埋めた後、以下をそのまま使う。

```
docs/course-design/inputs/hearing-log.md を読み込んでください。

これは講座のターゲット候補から集めた生の声です。以下を出力してください。

1. 繰り返し現れる悩みを、出現回数の多い順に列挙。
   その際、必ず本人の言葉をそのまま引用してください（言い換え禁止）。
2. 各悩みをHARMの4分類（健康・野心・人間関係・お金）に割り当て、
   主軸となる分類を1つ特定してください。
3. 表面的な要望と、その裏にある本当の悩みを分けてください。
   （例: 「集計を楽にしたい」の裏に「無意味な作業をしている自分が嫌だ」がある）
4. 顧客の言葉だけを使った講座名・キャッチコピーの候補を5つ。
   あなたの語彙を混ぜないでください。

推測で埋めず、記録に書かれていないことは「記録にない」と明示してください。
```

出力が抽象語（「効率化」「見える化」「最適化」）で埋まっていたら、生の声が足りない証拠である。
1-1に戻る。

### 競合の隙間（調査済み）

当初の仮説「既存研修は制約を明言しない」は**検証の結果、外れた**。
文科省ガイドライン Ver.2.0 が個人情報・著作権の留意点を主体別に明示しており、
制約の明言は業界標準である。**差別化ではなく前提条件**として扱う。

また「苦痛・不安から入る設計は誰もやっていない」も成立しない。
みんなのコードの「不安が『使ってみたい！』に変わる」研修が既に実装している。

調査で浮上した実際の隙間:

| # | 隙間 | 根拠 |
| --- | --- | --- |
| A | **研修後の定着（出口）** | 既存研修は研修の中を設計している。「自分の業務でどう使うか」の設計が手薄 |
| B | **学校ごとのできることの差** | セキュア環境の有無で扱える業務が根本的に違う。次世代校務DX導入済み自治体は6.1% |
| C | 研修が届いていない層 | 小規模自治体・未活用自治体は研修未実施の傾向。ただし予算も小さい |

**A を軸に置く。** 差別化になるのは制約の明言ではなく、
**参加者自身の業務が、その場で1つ終わること**である（工程0-3と一致）。

### ターゲットを広く取ることの影響

「広く学校現場の人」は確定方針である。ただし調査により、以下が実データで裏付けられた。

- セキュア環境の有無で、できる業務が根本的に違う（導入済み6.1%）
- 自治体規模で、研修の実施状況も生成AIへの慣れも違う
- 立場（担任／管理職／事務職員）で苦痛が違う

| 立場 | 想定される苦痛の中心（未検証） |
| --- | --- |
| 担任 | 授業準備の時間が取れない、事務作業、保護者対応 |
| 管理職 | 報告・集計・対外文書、教職員の負担管理 |
| 事務職員 | 定型書類、集計、問い合わせ対応 |

対象を絞らない以上、**内容側で差を吸収する**。[competitors.md](competitors.md) の
「『広く』で行く場合の設計」に4つの対処を記載した。要点は以下。

1. 冒頭でセキュア環境の有無を確認し、実演をどちらかに寄せる
2. 共通部分は**個人情報を入力しない前提で完結する業務**に絞る（全員に当てはまる範囲）
3. セキュア環境がある学校向けの内容は後半に分岐させる
4. **文科省動画で足りる内容は講座から外す**（仕組み・歴史・一般的注意点）

4番が最も効く。無料で手に入る内容に貴重な研修時間を使わないことが、参加者の時間を守る。
